# 000 原则

`/polish` 只做一件事：把一段粗糙的请求转写成规范提示词，交回给用户。五条边界决定一个功能能不能做；与它们冲突的改动改设计，不改边界。

| # | 原则 | 约束什么 |
| --- | --- | --- |
| P1 | 发送权在用户 | 插件只写输入框，不触发提交。「采用」之后由用户自己按发送。 |
| P2 | 浮层是唯一的输出面 | 结果出现在输入框上方的浮层，不进对话流，不进会话历史。 |
| P3 | 用户文本不进会话日志 | 转写走插件自己的 HTTP 路由，粗糙文本与规范提示词都不追加到会话事件。 |
| P4 | 会话只读 | 读会话的最近消息与模型选择；不写回、不改模型、不追加事件。 |
| P5 | 插件不碰文件系统 | 唯一的落盘是图片经宿主附件准入写进附件存储，那是发一条带图消息本来就要付的代价。 |

## 怎么用这五条

一个需求进来，按 P1 到 P5 逐条过。有一条不成立就改设计。

| 想做的事 | 挡路的原则 | 可行的做法 |
| --- | --- | --- |
| 采用后自动发送 | P1 | 只调 `setDraft`，发送留给用户 |
| 把结果做成对话流里的卡片 | P2 | 渲染在输入框上方浮层 |
| 把规范提示词 append 到 session | P3 | 只经 HTTP 回给 Client |
| 转写前替用户切到更强的模型 | P4 | 用会话当前模型，无记录时才用部署默认 |
| 把图片存进插件自己的目录再读 | P5 | 经 `admitPromptContent` 准入 |

## 范围

- 两个入口：输入框工具条的按钮、`/polish` 命令。两者共用一套逻辑。
- 一次一条提示词。不做模板库、不做批量。
- 没有配置项。轮次上限、超时、转写提示词都是 `index.js` 里的常量。
- 输出语言跟输入语言，不提供语言开关。
