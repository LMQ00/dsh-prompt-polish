# 测试

> 状态：策略已定，测试待实现。规则 D4：行为改动必须补对应自动化测试。

## 两层

| 层 | 谁跑 | 进 CI | 作用 |
| --- | --- | --- | --- |
| 自动化测试 | 机器 | 是 | 覆盖能机械判定的部分：解析、状态机、提示词组装、写入行为 |
| 盲读测试 | 人 | 否 | 覆盖「说清楚」这一主观目标；依赖模型行为，无法机械判定 |

诚实边界：自动化测试**不能**证明转写质量好，只能证明程序按契约运行。转写质量由盲读测试负责。

## 自动化测试清单

| 用例 | 断言 |
| --- | --- |
| 命令参数解析 | `/polish 有参` 用参数；`/polish` 用草稿；`/polish` + 空草稿 → `EMPTY_INPUT`；首尾空白被 trim |
| 参数优先 | 有参数时**不**读取也不修改草稿 |
| 状态机迁移 | 逐条覆盖 [data-model.md](data-model.md) 迁移表的每一行 |
| 追问上限 | 第 3 轮回答后必进 `review`（即使模型仍返回 `questions`），且稿中含假设标注 |
| 无缺口直出 | 模型首轮给稿 → 不出现 `clarifying` |
| 过期响应 | `requestId` 不匹配 → 结果被丢弃 |
| 会话切换 | 在途请求被丢弃，不写新会话输入框 |
| 错误映射 | 各类失败映射到 [api.md](api.md) 的错误码 |
| 写入行为 | 采用只调 `setDraft`；**断言 `submit` 从未被调用** |
| 不落盘 | 运行期没有任何 fs 写调用 |
| 不进会话 | 转写路径不触碰 `agentLoop`、不追加会话事件 |
| JSON 解析失败 | 按 `LLM_ERROR` 处理，不把裸文本写入输入框 |
| 提示词组装 | 出稿用的 system prompt 含四硬清单四项约束与「语言跟输入」约束 |

## 盲读测试（人工验收）

目的：验证生成的规范提示词**脱离上下文仍能被理解**。

步骤：

1. 准备 3 类粗糙输入：写代码 / 写文案 / 分析数据，各一句到一段。
2. 对每条：触发 `/polish`，走完追问（若有），在 `review` 态复制规范提示词全文。
3. **新开一个会话**（或换一个 AI），只粘贴这一段，不带任何补充说明。
4. 判定：
   - 对方直接开工，或只问它确实无法自行决定的问题 → **通过**
   - 对方反问「你到底想要什么 / 给谁用 / 输出成什么形式」这类规范版本可以写清的东西 → **不通过**
5. 3 条全通过才算通过；失败条目记录原文与反问内容，用于改提示词。

记录位置：结果与失败样本写进本文件下方的「盲读测试记录」。
