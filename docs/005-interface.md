# 005 界面

`/polish` 在 Harness Web GUI 的输入框区域有两块界面：工具条上的触发按钮，和按钮点开后出现在输入框正上方的浮层。浮层优先显示你此刻最需要决定的东西：模型在问你问题就显示问题，给出了成品就显示成品，出了错就显示原因和可以改的原文。概念见 [001 领域模型](001-domain.md)，阶段见 [003 生命周期](003-lifecycle.md)。

## 打开界面依次回答的问题

1. 这次要转写的东西是什么？——浮层标题写着阶段，输入态和失败态下面就是可编辑的原文框。
2. 模型还缺什么信息？——澄清态把问题按行铺开，每题 2 到 3 个选项加一行自由填。
3. 结果能不能用？——预览态只读展示规范提示词与假设，下面三个按钮：采用、不满意重试、放弃。

## 两块界面

| 位置 | 元素 | 显示什么 |
| --- | --- | --- |
| 输入框工具条，模型选择器左侧 | 触发按钮 | 一个四角星图标，26×26。浮层开着时图标变为品牌色 |
| 输入框正上方 | 浮层 | 标题栏 + 当前阶段的正文 + 底部按钮 |

触发按钮的提示文字是 `规范提示词（/polish）`，无障碍名是 `规范提示词`。`input`、`drafting`、`clarifying`、`review` 四态按钮置灰，`error` 态可再次点击。

## 浮层各阶段

阶段顺序与 [003 生命周期](003-lifecycle.md) 的阶段表一致。

| 阶段 | 标题 | 显示什么 | 底部按钮 |
| --- | --- | --- | --- |
| `input` | 规范提示词 · 输入请求 | 一个可编辑文本框，占位符 `输入你的需求` | 转写（文本为空时置灰）、关闭 |
| `drafting` | 规范提示词 · 转写中 | 一句 `正在转写…` | 无 |
| `clarifying` | 规范提示词 · 需要澄清 | 每题一段：问题 + 选项行 + 自由填行 | 继续、放弃、`最多再问 N 轮` |
| `review` | 规范提示词 | 只读成品、假设、覆盖提示 | 采用、不满意，重试、放弃 |
| `error` | 规范提示词 · 未完成 | 红色错误文案 + 可编辑原文框 | 转写、关闭 |

标题栏右侧固定有一个 `✕` 关闭按钮，无障碍名 `关闭`。

## 澄清态怎么读

每个问题是一段，从上往下：问题文本、选项行、自由填行。

| 元素 | 单选的形态 | 多选的形态 |
| --- | --- | --- |
| 选项徽标 | 序号 `1`、`2`、`3` | 空方框，选中后填 `✓` |
| 选中样式 | 底色加重 + 描边 | 同上 |
| 自由填行 | 笔形 `✎` | 方框，写了内容就填 `✓` |
| 自由填占位符 | 有选项时 `也可以直接写`，无选项时 `写下你的回答` | 同左 |

点击选项切换选中；点击自由填行把焦点放进输入框。提交时把选中的选项与自由填的内容用 `、` 连接成一个字符串，作为这一题的回答。

## 预览态怎么读

| 元素 | 内容 |
| --- | --- |
| 成品 | 等宽排版、可滚动的只读区块，最多 160px 高 |
| 假设 | `AI 的假设：` + 各条用 `；` 连接。没有假设时整行不出现 |
| 覆盖提示 | 输入框当前非空时显示 `采用后会覆盖输入框现有内容。` |
| 采用 | 把成品整段写进输入框，浮层关闭 |
| 不满意，重试 | 展开一个反馈输入框，占位符 `哪里不满意？（必填，会带进下一次转写）`；填了内容按钮才可用 |
| 放弃 | 关闭浮层，输入框不变 |

成品只读。要改就带反馈重试，或者采用之后回输入框改。

## 设计原则

1. **浮层不抢焦点。** 它挂在输入框上方，宽度对齐对话内容列，最高 45vh，超过就自己滚动，不推挤对话。
2. **一次只问一件事。** 澄清时只有问题和按钮，不混进成品预览。
3. **只读就是只读。** 成品区不是输入框；想改必须走重试，理由会进下一次请求。
4. **错误留在原地。** 失败态的原文框让用户接着改，不用重新写一遍。
5. **颜色全取主题 token。** 深色与浅色主题同时成立，不写死颜色值。
6. **不自动发送。** 「采用」只写输入框；发送永远是用户自己的动作。
