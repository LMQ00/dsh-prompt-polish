# 004 配置与提示词

这份文档列出装配一次转写时用到的全部文字，每段写在哪里、改动后怎么生效。概念见 [001 领域模型](001-domain.md)，上限值见 [002 规则与权限](002-rules.md)，阶段见 [003 生命周期](003-lifecycle.md)。

插件不声明 Config：`cordis.patch.yml` 只有一行 Host 注册，没有任何 `config` 段。所有文字都是源码里的常量，改动靠编辑源码，生效靠重启或刷新。

## 可编辑区表

| 区 | 装什么 | 位置 | 生效方式 |
| --- | --- | --- | --- |
| 系统提示词 | 转写规则：只输出 JSON、两种返回形状、四硬清单、语言约束、上下文用法 | `index.js` 的 `SYSTEM_PROMPT` | 重启 dsh |
| 用户轮拼装 | 上下文块、原始请求、已问答的澄清、不满意原因、问满轮次的指令 | `index.js` 的 `userPrompt()` | 重启 dsh |
| 命令描述与提示 | `/polish` 在 `/` 菜单里的说明与参数提示 | `index.js` 的 `apply()` | 重启 dsh |
| 错误文案 | 每个 `polish/*` 码对应的中文原因 | `index.js` 的 `translate()` 等处 | 重启 dsh |
| 浮层文案 | 标题、按钮、占位符、提示 | `client.js` 的渲染函数 | 硬刷新页面 |
| 样式 | 全部颜色取自 DSH 主题 token | `client.js` 的 `CSS` | 硬刷新页面 |

模型、轮次上限、超时、额度、输出 token 也是源码常量，见 [002 规则与权限](002-rules.md) §强度表。

## 装配顺序

一次请求的用户轮按下面顺序拼成，段落之间空一行。

1. 上下文块：`对话上下文（只用于消歧，不要复述）：` + 会话尾部若干行。没有上下文时整段不出现。
2. `原始请求：` + 粗糙文本。
3. 每一轮澄清：`已经问过并得到回答的澄清：`，然后逐题渲染 `Q: 问题` 与 `A: 回答`。未回答的写 `（未回答）`。
4. `用户对上一版不满意，原因：` + 用户填的理由。没有反馈时整段不出现。
5. `已经问满澄清轮次：不要再返回 questions，直接给出规范提示词，把仍未确定的信息写进 assumptions。` 只在预算用尽时出现。

最后一段是第 5 段，只在预算用尽时出现。它独立成段，改它不影响前面几段。

系统提示词与用户轮分开传：系统提示词走 `ctx.llm.stream({ system })`，用户轮走 `messages`。有图片时文本块在前、图片块在后。

## 优先级

从强到弱：

1. 代码强制的事实：JSON 结构校验、追问上限、图片白名单、额度、超时。
2. 系统提示词里的硬约束：四硬清单、语言跟输入、不复述上下文。
3. 用户轮里的指令：问满轮次时要求直接出稿。
4. 用户自己写的粗糙文本与澄清回答。

模型只读得到第 2 到第 4 层。第 1 层不经过模型：结构不认识就报 `polish/bad-output`，预算用尽就报 `polish/round-limit`，图片不合法就报 `polish/bad-image`。

## 版本与迁移

没有运行时配置，所以没有迁移：改源码、重启、跑测试，就是全部流程。

| 改动 | 要做的事 |
| --- | --- |
| 改 `SYSTEM_PROMPT` | 重启 dsh；重跑盲读测试，确认转写质量没退化 |
| 改用户轮拼装 | 重启 dsh；`test/host.test.js` 的提示词用例会断言段落内容 |
| 改浮层文案 | 硬刷新页面；`test/client.test.js` 不断言文案，靠人工看 |
| 改常量 | 重启 dsh；同步更新 [002 规则与权限](002-rules.md) 的强度表 |

转写提示词的验收标准是盲读测试：拿 3 类粗糙输入转写，把成品贴进一个没有任何上下文的新会话，对方能直接开工就算通过。
